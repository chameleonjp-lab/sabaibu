# 開発・検証ガイド

## 変更前の手順

変更対象を決めたら、まず責務の所有者と既存確認URLを特定します。戦闘なら`GameWorld.ts`、カメラなら`scene.ts`、HUD・タッチ操作なら`GameCanvas.tsx`と`index.css`から始めます。複数の攻撃経路や表示箇所へ同じ修正を複製する前に、共有の対象判定、ダメージ適用、スナップショット、レベル帯プロファイルがないか確認してください。

| 変更 | 主な確認対象 |
| --- | --- |
| 武器・敵・状態異常 | 対象選択、実ダメージ、撃破、統計、描画資産の破棄。 |
| 成長・ドロップ・ボス | 境界レベル、非境界レベル、報酬曲線、再出撃時のリセット。 |
| 移動・衝突・カメラ | 画面内外、障害物、キーボード、タッチ、縦横画面。 |
| HUD・モバイル操作 | safe area、操作レイヤー、横スワイプ、360×800、430×932、844×390。 |
| リザルト・統計 | 新規ラン、ゲームオーバー、遅延攻撃、総計と装備別内訳。 |

## 確認用URLの運用

視覚またはバランスの変更には、通常プレイを壊さない決定的な確認シナリオを用意します。既存URLはルートREADMEの[確認用URL](../README.md#確認用url)を参照してください。

新しいURLを追加する場合は、次の条件を守ります。

1. 通常プレイでは無効にする。
2. 問題を短時間で再現する最小の状態だけを作る。
3. HUDまたは画面上で、確認したい値・状態を読めるようにする。
4. READMEへパラメータと目的を追記する。

## 必須の品質ゲート

実装の変更後、PR作成前に以下を確認します。

```bash
pnpm check
pnpm build
```

| 検証 | 実施内容 |
| --- | --- |
| 型検査 | `pnpm check`。HUDスナップショット、攻撃発生源、入力イベントなどの契約ずれを検出。 |
| 本番ビルド | `pnpm build`。Viteの本番成果物を確認。chunk size警告は性能課題として記録し、成功判定と混同しない。 |
| 視覚確認 | 変更機能のURLを用い、PCと必要なモバイル画面比でスクリーンショットを取る。 |
| 実行ログ | ブラウザコンソールに`Error`、`TypeError`、`ReferenceError`がないことを確認。 |
| 回帰 | 変更した経路と、その共有境界を利用する代表的な既存経路を確認。 |
| メモリ | 検証後は不要なヘッドレスブラウザを終了し、メモリを解放する。 |

UI・カメラ・操作変更では、最低でも次のサイズを確認します。

| 表示領域 | 目的 |
| --- | --- |
| 360×800 | 細い縦長スマホでのHUD密度と安全領域。 |
| 430×932 | 標準縦長スマホでの情報量、仮想スティック、武器レール。 |
| 844×390 | コンパクト横画面でのヘッダー、スワイプレール、戦闘視界。 |

## モバイルUXのルール

フローティング仮想スティックは任意のタップ位置に出現し、背景、枠線、ノブ、ラベルを半透明に保ちます。操作のためにHUDを固定位置へ戻さないでください。カメラは画面比に応じて引き、プレイヤーだけでなく敵、障害物、封鎖壁を把握できる視界を維持します。

プレイヤー設定を追加する場合は、UI側で値の範囲をクランプし、GameHandleを通じてBabylonのカメラへ反映します。端末保存は読み込み失敗時に既定値へ安全に戻し、設定初期化が現在の出撃を再起動しないことを確認してください。

武器レールは横スワイプで全装備を見せます。表示本数を隠して情報を失うより、ネイティブ横スクロール、スナップ、端部フェード、細いスクロールバーを使って続きがあることを示してください。

## GitHub PR運用

GitHub連携を使う場合は、対象リポジトリの`main`、既存のオープンPR、ローカル差分を最初に照合します。WebDev管理用の`origin`がGitHubを直接指していない場合があるため、GitHub CLIで対象リポジトリとmainの先頭コミットを確認し、GitHub用の一時クローンまたは明示的なremoteで作業します。

PRには、以下を必ず含めます。

| PR項目 | 記載内容 |
| --- | --- |
| 概要 | ユーザーが体験できる変更を簡潔に説明。 |
| 実装 | 主なファイルと、共有境界で行った変更。 |
| 検証 | `pnpm check`、`pnpm build`、確認URL、モバイル表示の結果。 |
| 注意点 | 未検証の端末、既知の性能警告、後続のバランス調整候補。 |

コミット前には`git diff --check`、`git status --short`、変更ファイル一覧を確認し、生成物、秘密情報、無関係なログを含めないでください。

## 継続改修スキル

既存のBabylon.jsサバイバルゲームへ安全に変更を加えるための再利用スキルとして、`babylon-survivor-iteration` を用意しています。戦闘、進行、モバイル入力、レスポンシブHUD、統計、デバッグ、確認URL、品質ゲートを横断する変更で使用します。
